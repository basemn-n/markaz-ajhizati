# مركز أجهزتي — نسخة 0.6.0

مشروع أولي يتكون من:
- واجهة ويب عربية قابلة للتثبيت (PWA).
- تطبيق Android أصلي باستخدام Kotlin وJetpack Compose.
- خادم FastAPI مع تسجيل الحسابات وتسجيل الدخول وقوائم الأجهزة والربط بموافقة الطرف المستهدف.

## الروابط المنشورة
- الواجهة: https://markaz-ajhizati.onrender.com
- API: https://markaz-ajhizati-api.onrender.com

## تطبيق Android
يتم بناء نسخة APK تجريبية تلقائيًا عبر GitHub Actions عند تحديث ملفات تطبيق Android على فرع `main`. افتح تبويب **Actions** في GitHub، ثم اختر آخر تشغيل باسم **Build and install-test Android APK**، وبعد نجاحه نزّل artifact باسم `markaz-ajhizati-installfix-apk` وفك ضغطه لتجد `app-debug.apk`. ويمكن أيضًا فتح المشروع في Android Studio باستخدام JDK 17 وAndroid SDK 35 وتشغيل `:app:assembleDebug`.

التطبيق يتصل بخادم API عبر HTTPS، ويدعم تسجيل الدخول أو إنشاء حساب، ثم يسجّل الهاتف ضمن قائمة أجهزة الحساب. يستخدم التطبيق رمز الدخول في الذاكرة فقط؛ تسجيل الخروج أو إغلاق التطبيق ينهي الجلسة المحلية، وقد تحتاج إلى تسجيل الدخول مجددًا.

**مهم:** تسجيل الهاتف وقبول ربط الحسابات لا يفعّلان التحكم عن بُعد. لا توجد حتى الآن ميزة فعلية لعرض الشاشة أو الوصول إلى الملفات أو التحكم بالجهاز. ستحتاج هذه الوظائف إلى تنفيذ مستقل، وموافقة صريحة من صاحب الهاتف، وصلاحيات Android النظامية، وإمكانية إيقاف الاتصال وإلغاء الربط.

يُرفع APK الذي اجتاز اختبار التثبيت والتشغيل كـ artifact في GitHub Actions لمدة 14 يومًا. عند إعداد أسرار التوقيع الدائم يُوقّع بمفتاح الإصدار؛ وإلا يستخدم توقيع Debug للاختبار.

## إعداد خادم API
راجع `server/DEPLOY.md` لإعداد خدمة API على Render. يجب ضبط `MARKAZ_AUTH_SECRET` بقيمة عشوائية سرية لا تقل عن 32 حرفًا، واستخدام قاعدة بيانات PostgreSQL دائمة. لا تضع أسرار الخادم داخل تطبيق Android.

## تشغيل خادم API محليًا
```bash
cd server
python -m venv .venv
pip install -r requirements.txt
uvicorn main:app --reload
```

افتح `http://127.0.0.1:8000/docs`.

## نشر واجهة الويب على Render
راجع `RENDER_DEPLOY.md`. نشر الواجهة وحدها لا ينشئ تطبيق Android ولا يفعّل التحكم الفعلي بالأجهزة.
